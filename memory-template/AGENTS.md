## 记忆分两层（判据：**会不会过期**）

**① 项目知识 · `.agents/memory/knowledge/`** —— 描述「项目现在是什么样」，长期有效、**换人接手照样成立**。

| 文件             | 什么时候读                                              | 本项目是否有       |
| ---------------- | ------------------------------------------------------- | ------------------ |
| `conventions.md` | 改样式 / 改令牌 / 改页面前                              | 有 UI / 样式规范时 |
| `backend.md`     | 改 SQL / 接口 / 缓存 / 上传前                           | 有 API / DB 时     |
| `deploy.md`      | 部署 / 运维 / 备份恢复前                                | 要上线时           |
| `pitfalls.md`    | 踩到怪现象（工具 / 环境 / CSS）时                       | **任何项目都要**   |
| `verify.md`      | 要验证某项改动时                                        | **任何项目都要**   |
| `log.md`         | 查「某功能当时怎么做的 / 为什么」时（**写代码别通读**） | **任何项目都要**   |

**② 个人状态 · `.agents/memory/status/`** —— 描述「此刻做到哪了」，**会过期，闭环后当天删**。

| 文件     | 内容                            |
| -------- | ------------------------------- |
| `ops.md` | 进度 / 待办 / 待定项 / 部署现状 |

> ⚠️ 两类都要读时，**先读 knowledge，status 只用来定位「下一步做什么」**。
> ⚠️ **写新条目前的三问**：① 它描述「东西是什么样」还是「我做到哪了」？② 项目暂停半年后它还成立吗？③ 是不是别处已有（代码 / git / 文档）？
> 三问都过才写进 memory；否则不写或写进 status。

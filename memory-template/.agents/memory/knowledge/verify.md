## B. 最可靠的断言方式

- **首选：对「产物」断言** —— 序列化输出、日志、返回值、构建产物、直出的 HTML。
  比对界面交互或截图断言稳（不受渲染时序、无头环境差异影响）。
- **构造边界输入**：用空值 / 极值 / 异常数据强制走到目标分支，比临时改常量、改阈值安全
  （若确实改了常量，**断言完立即还原**）。
- **依赖要「真」**：验证降级 / 断连分支时，真停掉或断开依赖，不要用 mock 假装它挂了。

## D. 验证纪律（踩过的教训）

- **测试数据用完立即清理 / 还原**，并在报告里明确写「已还原」。
- **别把「环境伪影」当 bug**（缓存、转场动画、类型检查误报、过期的构建产物）。
- **A/B 对照不要拿「正在跑的实例」当旧版本**（它可能已经热重载成新版）。
- **改完必须复核 diff**：编辑工具偶发错位拼接，别只信「操作成功」。
- ⚠️ **跑写接口 / 写库验收前，基线必须在「任何写操作之前」采集**，否则没有可比对的起点。
- ⚠️ **带回退的探测命令会掩盖失败**：失败后自动换条路又成功的命令，报告前必须确认实际走的是哪条路径。

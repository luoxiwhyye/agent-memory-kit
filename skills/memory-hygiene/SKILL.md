# Memory Hygiene：记忆的分层与维护

目标：**让 AI 记忆长期可读、可维护、不会腐烂。** 记忆的价值不在「记了多少」，
而在「下次用的时候找得到、且是对的」。

## 一、判据：一条信息该不该写进记忆

写之前问三问，**都过才写**：

```
① 它描述「东西是什么样」，还是「我做到哪了」？
   ← 前者 = 项目知识（长期）    后者 = 个人状态（会过期）

② 这个项目暂停半年后，这条还成立吗？
   ← 成立 = 项目知识            失效 = 个人状态

③ 别处已经有了吗？（代码 / git log / 项目文档）
   ← 有 = 不写，最多留一行指针
```

还有一个**反向**判据 —— 什么时候**必须**写：

```
「下一次对话没有它，我就会做错事」→ 必须写
「它只是当时怎么做的」             → 不写（git 与代码已经是记录）
```

## 二、两层结构与各自的位置

| 层 | 位置 | 特征 | 写什么 |
| --- | --- | --- | --- |
| **入口** | `<repo>/AGENTS.md` | **每次对话自动加载** → 必须精简 | 项目结构 / 启动、高频铁律、索引表 |
| **项目知识** | `.agents/memory/knowledge/` | 长期有效、换人接手照样成立 | 约定、后端契约、部署规则、坑、验证手段、历史流水 |
| **个人状态** | `.agents/memory/status/` | **会过期，闭环后当天删** | 进度、待办、待定项、当前环境状态 |

**关键约束**：入口文件会被自动加载，所以**它有体量上限**（建议 ≤100 行）。
超出的内容一律推到 knowledge/ 子文件，入口只留一行摘要 + 「什么时候去读它」。

## 三、写条目时的格式纪律

- **一条只讲一件事**；用「现象 → 根因 → 对策」，**不写排查过程**。
- 保留：**根因**（为什么这么改）、**关键取舍**（为什么选 A 不选 B）、**踩到的坑**（错误做法 → 正确做法）。
- 压掉：重复罗列验证命令、同一结论的多种表述、纯试错步骤（除非试错本身就是坑）。
- **写「当前规则」，不写变更史**：不要写日期、轮次、「已修 / 原先 XX 是…」。
  变更史属于单独的变更史文档，不属于记忆。
- **面向 AI 的长文本禁用非 BMP 字符**（码点 > U+FFFF 的 emoji）：长会话中被截断
  会留下孤立代理 → 请求 400。改用 `● ○ ■ ★ ▲ →` 等单码元符号。

## 四、生命周期：升级与回收（这是防腐的关键）

```
流水（log.md）里的结论
        ↓ 当它变成「以后每次都要遵守」
规则（conventions.md / backend.md / …）      ← 搬家，不是复制；原地留一行指针
        ↓ 当它变成「每轮都必须知道」
入口（AGENTS.md）                            ← 只留一行，详情仍在子文件
```

**回收**：
- `status/` 的内容**闭环后当天删**。拿不准就压成一行指针，指向上游文档。
- 发现记忆与代码不符时：**以代码为准**，改记忆（或标注「已作废」并说明原因）。
  ⚠️ 不要只删掉旧结论 —— 留一句「XX 已不成立，因为 YY」，否则下次还会有人按旧结论做。

## 五、最常见的几种腐烂方式（对照自检）

| 症状 | 病因 | 处理 |
| --- | --- | --- |
| 文件长到几百 KB，没人读 | 把「过程」当「知识」写 | 砍掉验证/排查过程，只留结论与根因 |
| 同一件事写了 3~7 遍 | 每一轮都追加、不回头合并 | 合并成一处，写「最终态」 |
| 记录了已被推翻的做法 | 只追加不删除 | 删或标作废 + 说明原因 |
| 自相矛盾（同一文件两处冲突） | 局部更新、没通读 | 以最新/代码为准，统一 |
| 入口文件越写越长 | 把子文件内容抄了上来 | 只留索引与铁律，详情移回子文件 |

## 六、维护动作清单

**新增条目时**
1. 用「一、判据」定层。
2. 找**已有的**同类文件（不要新建文件，除非确实是新主题）。
3. 检查是否与既有条目重复/矛盾 —— **先搜再写**。

**定期整理时**（或用户要求精简时）
1. 先备份（把当前文件复制一份，带日期）。
2. 通读一遍，给每条定去向：删 / 压 / 并 / 升 / 迁 —— **不允许「悬空」**。
3. 合并重复主题；删掉已被推翻的中间态。
4. 把升级成规则的条目**搬**到对应子文件（搬，不是复制）。
5. 验收：**抽查关键主题是否都还有归属**（这是防信息丢失的主要手段）。

## 七、本技能不做的事

- 不修改项目源代码（那是别的技能的事）。
- 不执行 `git commit` / `push` / `add` —— 只写文件，提交交给用户。
- 不把记忆写进**跨项目的个人记忆**（user memory / 全局配置）：
  项目专属知识一旦进去，会污染其它项目。
